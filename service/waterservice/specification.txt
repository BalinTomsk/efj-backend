Recreate this project as a Java 21 Spring Boot background service named `water-station-pusher`.

Goal
- Poll supported Canadian water stations from MSSQL.
- Download each station's hourly hydrometric CSV from Environment Canada.
- Parse readings and upsert them into `dbo.WaterData`.
- Disable a station after 3 fetch failures in the same calendar day.

Tech stack
- Java 21
- Maven
- Spring Boot 3.2.x
- `spring-boot-starter`
- `spring-boot-starter-jdbc`
- `spring-boot-starter-aop`
- MSSQL JDBC driver
- Resilience4j Spring Boot 3 integration for SQL retry/circuit breaker
- `commons-csv` dependency may be included, but simple CSV parsing is acceptable
- `dotenv-java` for local credential loading
- SLF4J + Logback

- If env vars are missing, try loading a root-level `.env` file with `dotenv-java`.
- Support optional `DOTENV_PATH` env var to point to a custom `.env` file.

  - `DB_URL`
  - `DB_USERNAME`
  - `DB_PASSWORD`

Datasource config

Worker behavior
- Implement a background worker started via `ApplicationRunner`.
- If app is started with `--console`, do not launch the background thread.
- Otherwise start a non-daemon thread named `water-station-worker`.
- The worker loops forever:
  - Load supported stations from DB
  - Process stations one by one
  - Sleep between stations
  - Sleep between full cycles
- Configurable properties:
  - `water.worker.pause-between-stations-ms` default `1500`
  - `water.worker.pause-between-cycles-ms` default `300000`
  - `water.worker.connect-timeout-ms` default `15000`
  - `water.worker.read-timeout-ms` default `30000`

Console mode
- Add a console/debug runner activated by `--console`
- Optional arg: `--station=<MLI>`
- In console mode, run exactly one processing pass
- If `--station` is provided, process only that station from the supported station list

WaterStation query rules
- Read from table `WaterStation`
- Select columns:
  - `mli`
  - `state`
  - `tz` using `ISNULL(tz, 0)`
- Filter:
  - `country = 'CA'`
  - `supported = 1`
- Ignore unsupported stations
- Represent each row as a simple record like `StationRef(String mli, String state, int tz)`

CSV fetch rules
- URL pattern:
  - `https://dd.weather.gc.ca/today/hydrometric/csv/{STATE}/hourly/{STATE}_{MLI}_hourly_hydrometric.csv`
- Example:
  - `https://dd.weather.gc.ca/today/hydrometric/csv/QC/hourly/QC_02JE025_hourly_hydrometric.csv`
- Use `HttpURLConnection`
- Set connect/read timeouts from config
- Set a basic browser-like `User-Agent`
- Non-200 response should be treated as failure

CSV parse rules
- Skip the first row as header
- Ignore rows with fewer than 7 columns
- Parse:
  - column 0 -> station id
  - column 1 -> timestamp as `OffsetDateTime`
  - column 2 -> water level
  - column 6 -> discharge
- Trim string values
- Empty numeric values should map to `null`
- Model each reading as:
  - `Reading(String stationId, OffsetDateTime stamp, Double waterLevel, Double discharge)`

Failure handling
- Track failures in memory per station
- Failure counter resets when the date changes
- On any station processing exception:
  - increment today's failure count for that station
  - log the failure count
- When a station reaches 3 failures in the same calendar day:
  - execute `UPDATE WaterStation SET supported = 0 WHERE mli = ?`
  - remove that station from in-memory failure tracking

WaterData persistence rules
- Implement repository method `saveStationData(String mli, List<Reading> readings)`
- Ignore blank `mli`
- If readings list is null or empty, do nothing
- Wrap save in one transaction
- Apply Resilience4j retry and circuit breaker around SQL operations
- Upsert each reading using `(mli, stamp)` as the natural key
- Use SQL Server `MERGE`
- Mapping:
  - CSV water level -> `dbo.WaterData.elevation`
  - CSV discharge -> `dbo.WaterData.discharge`
- Store timestamp as SQL `datetime2`

Expected SQL shape
```sql
MERGE dbo.WaterData AS trg
USING (
    SELECT
        CAST(? AS varchar(64)) AS mli,
        CAST(? AS datetime2)   AS stamp
) AS src
ON trg.mli = src.mli
   AND trg.stamp = src.stamp
WHEN MATCHED THEN
    UPDATE SET
        elevation = ?,
        discharge = ?
WHEN NOT MATCHED THEN
    INSERT (mli, stamp, elevation, discharge)
    VALUES (src.mli, src.stamp, ?, ?);
```

Resilience4j settings
- Retry instance name: `sqlRetry`
- Circuit breaker instance name: `sqlBreaker`
- Retry:
  - max attempts `3`
  - wait duration `2s`
  - retry `org.springframework.dao.DataAccessException`
  - retry `java.sql.SQLException`
- Circuit breaker:
  - sliding window size `10`
  - minimum number of calls `5`
  - failure rate threshold `50`
  - wait duration in open state `30s`

  - save start/end with reading counts
  - failures and station disable events
