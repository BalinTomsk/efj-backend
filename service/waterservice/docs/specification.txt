Recreate this project as a Java 21 Spring Boot background service named `water-station-pusher`.

Goal
- Poll supported Canadian and US water stations from MSSQL.
- Download each CA station's hourly hydrometric CSV from Environment Canada.
- Download each US station's WaterML payload from USGS.
- Parse readings and upsert them into `dbo.WaterData`.
- After each worker pass, synchronously run `dbo.spCleanWeatherWaterData` and then `dbo.spPushSpeciesFromLakeToStation`.
- Log processing failures and skipped unpublished-source events, but do not disable stations automatically.

Tech stack
- Java 21
- Maven
- Spring Boot 3.2.x
- `spring-boot-starter`
- `spring-boot-starter-jdbc`
- `spring-boot-starter-aop`
- MSSQL JDBC driver
- Resilience4j Spring Boot 3 integration for SQL retry/circuit breaker
- `commons-csv` dependency may be included, but simple CSV parsing is acceptable
- `dotenv-java` for local credential loading
- SLF4J + Logback

Worker behavior
- Implement one `StationWorker` started via `ApplicationRunner` that launches separate CA and US background threads.
- If app is started with `--console`, do not launch either background thread.
- Otherwise start non-daemon threads named `water-station-worker-ca` and `water-station-worker-us`.
- Each worker loops forever:
  - Load supported stations for its country from DB
  - Process stations one by one
  - Sleep 1 second between stations
  - After the station pass completes, synchronously run post-processing procedures in this order:
    - `dbo.spCleanWeatherWaterData`
    - `dbo.spPushSpeciesFromLakeToStation`
  - Sleep until the next top-of-hour between full cycles when the cycle finishes early
  - Start the next cycle immediately when processing has already run past that hour boundary
- Configurable properties:
  - `water.worker.pause-between-stations-ms` default `1000`
  - `water.worker.connect-timeout-ms` default `15000`
  - `water.worker.read-timeout-ms` default `30000`

Console mode
- Add a console/debug runner activated by `--console`
- Optional arg: `--station=<MLI>`
- In console mode, run exactly one processing pass for both country workers in parallel
- If `--station` is provided, pass that filter to both workers and process only matching supported stations
- Each worker still performs its own post-processing sequence after its pass completes

WaterStation query rules
- Read from view `vwWaterStation`
- Select columns:
  - `mli`
  - `state`
  - `tz`
- Filter:
  - `country = 'CA'` for the CA worker
  - `country = 'US'` for the US worker
- Represent each row as a simple record like `StationRef(String mli, String state, int tz)`

CSV fetch rules
- URL pattern:
  - `https://dd.weather.gc.ca/today/hydrometric/csv/{STATE}/hourly/{STATE}_{MLI}_hourly_hydrometric.csv`
- Example:
  - `https://dd.weather.gc.ca/today/hydrometric/csv/QC/hourly/QC_02JE025_hourly_hydrometric.csv`
- Use `HttpURLConnection`
- Set connect/read timeouts from config
- Set a basic browser-like `User-Agent`
- Non-200 response should be treated as failure
- HTTP 404 should be surfaced as `FileNotFoundException` semantics so the station can be skipped

US fetch rules
- URL pattern:
  - `https://waterservices.usgs.gov/nwis/iv/?sites={MLI}&period=P3D&format=waterml`
- Use `HttpURLConnection`
- Set connect/read timeouts from config
- Set a basic browser-like `User-Agent`
- Non-200 response should be treated as failure
- HTTP 404 should be surfaced as `FileNotFoundException` semantics so the station can be skipped
- Retry transient `IOException`s up to 3 attempts for:
  - `EOFException`
  - `SocketTimeoutException`
  - `SocketException`
  - messages containing `Premature EOF`

CSV parse rules
- Skip the first row as header
- Ignore rows with fewer than 7 columns
- Parse:
  - column 0 -> station id
  - column 1 -> timestamp as `OffsetDateTime`
  - column 2 -> water level
  - column 6 -> discharge
- Trim string values
- Empty numeric values should map to `null`
- Model each reading as:
  - `Reading(String stationId, OffsetDateTime stamp, Double waterLevel, Double discharge)`

US parse rules
- Parse USGS WaterML into one stored-procedure payload per variable
- Preserve variable metadata and XML payload content in `UsSeriesReading`
- Reduce values to daily entries before building the stored-procedure payload

Failure handling
- On any station processing exception:
  - log a warning with country, station, and state
  - continue processing remaining stations
- For CA or US source HTTP 404 responses:
  - log that the source feed is not published
  - do not disable the station
- Do not execute `dbo.sp_DisableWaterStation` in the current project state

WaterData persistence rules
- Implement repository method `saveStationData(String mli, List<Reading> readings)`
- Reject blank `mli`
- If readings list is null or empty, do nothing
- Wrap save in one transaction
- Apply Resilience4j retry and circuit breaker around SQL operations
- Deduplicate readings by timestamp within the batch, keeping the last duplicate
- Upsert each reading by executing legacy stored procedure `dbo.sp_UpdateWaterData`
- Mapping:
  - CSV water level -> `dbo.WaterData.elevation`
  - CSV discharge -> `dbo.WaterData.discharge`
- Store timestamp as SQL `datetime2`
- Also implement `saveUsStationData(String mli, String state, List<UsSeriesReading> seriesList)`
- Use the legacy stored procedure `dbo.sp_push_us_water_data`
- Also implement post-processing repository methods:
  - `cleanWeatherWaterData()` -> `dbo.spCleanWeatherWaterData`
  - `pushSpeciesFromLakeToStation()` -> `dbo.spPushSpeciesFromLakeToStation`

Important note about delete logic
- There was earlier intent to delete old `WaterData` rows older than 15 days for a station.
- In the current project state that delete is not active.
- Recreate the current behavior as-is unless explicitly told to restore the cleanup query.
- The cleanup now happens only through the post-processing procedure `dbo.spCleanWeatherWaterData`.

Resilience4j settings
- Retry instance name: `sqlRetry`
- Circuit breaker instance name: `sqlBreaker`
- Retry:
  - max attempts `3`
  - wait duration `2s`
  - retry `org.springframework.dao.DataAccessException`
  - retry `java.sql.SQLException`
- Circuit breaker:
  - sliding window size `10`
  - minimum number of calls `5`
  - failure rate threshold `50`
  - wait duration in open state `30s`
